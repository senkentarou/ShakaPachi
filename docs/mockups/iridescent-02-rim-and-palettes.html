案C-1：リム静止（前回のもの）

macOS 13 で可

比較の基準。角度が固定なので、選択が動いてもリムの色は変わりません。

案C-2：リムがゆっくり回る

本命 macOS 13 で可

conic グラデの角度をゆっくり回すだけ。Swift ではリム用の CAGradientLayer に CABasicAnimation(keyPath: "transform.rotation.z") を無限リピートで1回仕込むだけで、 以後メインスレッドは毎フレーム何もしません（描画はレンダーサーバ側）。 パネルは修飾キー押下中しか出ないので、アニメーションが回るのも実質その数百ミリ秒〜数秒だけです。

案C-3：選択を動かすとリムの角度が飛ぶ

macOS 13 で可

アニメーションを常時回さず、選択移動のタイミングだけ角度を進める案。連続再描画がゼロのまま「動いている」感じが出ます。 既存の moveSelection にそのまま乗ります。

↑ タイルをクリック、または ← → キーで選択を移動してみてください

案C-4：リム ＋ ほんのり発光

macOS 13 で可

リムの外側に淡いブルームを足したもの。「AI ボタン」らしさは一番強いが、主張も一番強い。

「流れるアニメーション」はどこまで出せるか

前回「macOS 13 では不可」と書いたのは言い過ぎでした。正しくは 回転・色送り・移動は出せる／シェーダ級の有機的なうねりは出せない、です。

やりたい動きCore Animation で出せるか使うプロパティ
虹色が回る✅ 出せるtransform.rotation.z / conic の endPoint
色が送られる・入れ替わる✅ 出せるCAGradientLayer.colors（アニメーション可能）
光沢が斜めに流れる✅ 出せるlocations / レイヤの position
色の塊がゆっくり漂う✅ 出せる複数レイヤの transform を別周期で
マーブルの脈が有機的にうねる❌ シェーダが要るfBm ノイズ＋ドメインワーピング（macOS 14+ / 15+）

左は「マーブルが流れている」ように見えますが、中身はぼかした円を別々の周期で漂わせているだけで、 ノイズは一切使っていません。この手の表現は目が細部を追えないので、近似でかなりのところまで行きます。 ただし前回の指摘どおりパネル全体でやると視認性が落ちるので、実用は右（リム限定）です。

パレットについて

上のバーで全体を切り替えられます。「紫っぽいやつ」は Gemini 系で、 青 → 紫 → ピンク（Google Blue から紫を通って赤紫へ）という並びが特徴です。 Apple Intelligence 系はピンク・橙・青・紫を淡く散らした構成、Copilot 系は紫〜シアンの寒色寄り。 なお 色の並びは各社ブランドの「系統」を寄せたもので、正確なブランドカラーではありません。 そのまま使うと他社ブランドを想起させるので、採用するなら shakapachi 側に寄せた調整が要ります。

リムは面積が小さいぶん彩度が必要で、パネル全体に効かせた時とは最適な色が変わります。 淡い「玉虫」はパネル全体向き、はっきりした「Gemini 系」はリム向き、という傾向が見えるはずです。

次の判断ポイント：案C-2（常時ゆっくり回転）か 案C-3（選択移動時だけ角度が飛ぶ）か、 ＋ どのパレットか、＋ リムの太さ。決まれば Swift 実装（CAGradientLayer.type = .conic ＋ CABasicAnimation）に落とします。
